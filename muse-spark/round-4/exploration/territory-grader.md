## What it does

Round 3's entry ([`muse-spark/round-3/exploration/territory-grader.md`](../../round-3/exploration/territory-grader.md), frozen) mapped the grader through ADR 0011/0013: bit-exact G2 at six sizes, paired timing at all six sizes, two-phase `beats_compiled`, the `max_rows` hand-off, and the ready check that judged each `muse-*` variant on its own pass. Round 4 changes three rules ([ADR 0015](../../../claude/adr/0015-sets-and-hand-off-below.md)): an attempt may also hand off below `min_rows`; a handed-off size is reported `handed off` and is not timed against the compiled reference; and candidates that pass together as `muse-all` are `ready` as a **set**. This entry writes only that delta. G1/G2 mechanics, the spec language apart from the two bounds, `capture`, `gpu_lock`, the chained timing and the G3 range rule are cited to round 3, not re-described. The grader was not run and no GPU work was done for this entry; unit-test and re-grade results below are cited to ADR 0015, not re-measured.

## The exact boundary a round-4 solution must keep

A round-4 attempt is inside the boundary only if all five hold. This is the checklist the builders, the boundary agent and the checker grade against; each line names its source.

1. **Spec validity.** `min_rows` and `max_rows` in `spec.json` are each an integer of at least 1, booleans and floats refused, and `min_rows ≤ max_rows` when both are given — otherwise `build()` raises `ValueError` before any kernel runs and the attempt is a G1 failure ([slots.py:330-335](../../../bench/grader/slots.py); brief:174). For `routing+combine` each part's spec carries its own pair of bounds (brief:176).
2. **Inclusive kernel window.** The attempt's kernels run exactly when `min_rows ≤ rows ≤ max_rows` for the bounds it gives (a missing bound is open on that side), and run the slot's reference under `mx.compile` outside that window; `rows` is the first slot input's `shape[0]` ([slots.py:338-345](../../../bench/grader/slots.py)). Row-for-row: `hands_off(rows)` is `rows > max_rows or rows < min_rows` ([slots.py:338-339](../../../bench/grader/slots.py)), and `test_hand_off.py` pins the edges bit-for-bit: 8 and 59 run the kernel, 7 and 60 run the compiled reference, for `min_rows: 8, max_rows: 59` ([test_hand_off.py:69](../../../bench/grader/test_hand_off.py)).
3. **G2 bit-exactness at every size, handed off or not.** G2 runs the attempt's `run()` — hand-off dispatch included — on all 20 layers at 1, 8, 32, 127, 1,016 and 2,048 rows and requires bit-for-bit equality with the plain reference, in order for routing (including the tied 4th/5th choice) and elementwise for combine/experts; timing runs only if G2 passes ([check_candidate.py:320-351](../../../bench/grader/check_candidate.py); brief:187-195,175). A handed-off size therefore tests `mx.compile(reference)` against the plain reference through the attempt's own dispatch, which is why the boundary also includes compiled==reference at the six sizes (round-3 entry §2; [ADR 0011:34](../../../claude/adr/0011-decode-and-prefill.md)). For experts the window must also sit on the right side of MLX's 60-row kernel switch (`gather_qmm_rhs` from 60 rows, different rounding): a decode-built experts kernel may run only below 60 rows, i.e. `max_rows ≤ 59` ([slots.py:219-220](../../../bench/grader/slots.py); round-3 entry §2). Inside the window the reference still changes behaviour once: `ref_experts` sorts the pairs from 16 rows (`inds.size >= 64`, [slots.py:62](../../../bench/grader/slots.py)), so a kernel running at both 8 and 32 rows must match the unsorted and the sorted reference, both on the `gather_qvm` side of 60.
4. **Piece-timing phase rule.** At each timed size the verdict is `faster` with ≥22 wins of 30 paired repeats, `slower` with ≥22 losses, else `same` ([check_candidate.py:244-250](../../../bench/grader/check_candidate.py)). `judge()` drops `handed off` sizes from their phase: a phase is `faster` only when **every** size the kernels run at is `faster` and at least one such size exists, `slower` when any timed size is `slower`, `handed off` when none is left, else `not slower`; `beats_compiled` is true iff one phase is `faster` and neither is `slower` ([check_candidate.py:253-271](../../../bench/grader/check_candidate.py); brief:217-218). One `same` at a timed size blocks the bar; one `slower` anywhere fails it.
5. **Whole-request rule, and the set.** The ready check and G3 time whole requests in vLLM at 1×128, 8×128, 32×128, 32×1024 (5 repeats, 256 tokens), require the same greedy tokens at 1 and 32 requests, and pass a variant only when decode or prompt is `faster` (non-overlapping ranges) in every workload and nothing — decode, prompt or whole request — is `slower` anywhere ([check_ready.py:47-56,131-161](../../../bench/grader/check_ready.py); [time_candidates.py:163-201](../../../bench/grader/time_candidates.py)). From round 4, when `muse-all` passes, its candidates are `ready` together as a set even where one fails alone, and G3 judges the set as one (skill step 4; brief:206; [ADR 0015:11,42](../../../claude/adr/0015-sets-and-hand-off-below.md)). The converse also binds: with 1 request every decode step has 1 row, so an attempt with `min_rows: 2` runs MLX's own code for the whole 1×128 workload and can pass G3/the ready check only inside a set whose other kernels are faster there (brief:174; [ADR 0015:37](../../../claude/adr/0015-sets-and-hand-off-below.md)).

## Checklist

### 1. `slots.py` `build()` — `min_rows`/`max_rows` and `hands_off` (slots.py:304-368)

- **Callers:** `check_candidate.load` ([check_candidate.py:70-77](../../../bench/grader/check_candidate.py)), and through it `time_candidates.Variants`/`implementations` and the ready check — so the same dispatch, bounds included, runs in G2, the piece timing, G3 and the ready check. For `routing+combine`, `load` splits the folder spec into per-part specs and builds each part separately, so each part hands off by its own bounds ([check_candidate.py:76-77](../../../bench/grader/check_candidate.py); brief:176).
- **Callees:** `mx.fast.metal_kernel` per spec kernel (built once per `build` call), and `compiled = mx.compile(REFERENCE[slot])`, also built once per call whether or not the spec gives bounds ([slots.py:336](../../../bench/grader/slots.py)). `run()` calls `compiled(*inputs)` in slot-input order and re-zips to slot outputs on a hand-off ([slots.py:341-345](../../../bench/grader/slots.py)).
- **Data:** unchanged from round 3 (`SLOTS`, brief slot tables); the only new data is the two optional spec integers. `rows` is read from the first slot input's `shape[0]` for both dispatch and grid evaluation ([slots.py:342](../../../bench/grader/slots.py)).
- **Neighbours:** before it, the spec validation refuses a bad bound as a `ValueError`, which `check_candidate` reports as G1 (`result["error"]`, [check_candidate.py:401-402](../../../bench/grader/check_candidate.py)); after it, `run.hands_off` is the attribute the timing loop consults (piece 2). The threadgroup product ≤1024 check is unchanged ([slots.py:348-350](../../../bench/grader/slots.py)); threadgroup memory is still not checked (round-3 *can't see* item 8 stands).
- **Cost:** `build` launches no kernel itself. The hand-off branch is one Python comparison per `run()` call; in G3/ready-check serving that call happens per layer per step through `make_moe_call`, and any wrapper cost there is inside the whole-request times, not the piece timing (piece 2, *can't see* item 2). No new measured number is claimed here.
- **Invariants:** the inclusive window and the refusal rules in *The exact boundary* items 1–2; validation rejects `bool` explicitly because `True` is an `int` in Python ([slots.py:331-333](../../../bench/grader/slots.py)), and `min_rows > max_rows` is refused with "the kernels would never run" ([slots.py:334-335](../../../bench/grader/slots.py)). What `build` does **not** check: that the window sits on the right side of 60 for experts, or anything about rows between the tested sizes (see *What each tool still cannot see*).

### 2. `check_candidate.py` — handed-off sizes not timed, `judge()` and `beats_compiled` (check_candidate.py:244-271, 352-400)

- **Callers:** builders, `.venv/bin/python bench/grader/check_candidate.py <attempt> <slot> [--out FILE]`; no `--baseline` this round — no slot has one (round-4 README *Starting point*), so the only bar is `compiled`. The `--baseline` path still exists and its handed-off rule differs (below), which a reader of a baseline grade must not confuse with the compiled bar.
- **What is new — exclusion, not a tie.** Per part and size, the timing loop builds `together = {candidate, compiled[, baseline]}` and then drops every function except `compiled` whose `hands_off(rows)` is true, so a handing-off function is never run in `paired_times` at that size ([check_candidate.py:372-380](../../../bench/grader/check_candidate.py)). Its per-repeat times are then taken from the compiled function's repeats (`paired.get(name, paired["compiled"])`) and summed across parts as before ([check_candidate.py:381-384](../../../bench/grader/check_candidate.py)). Consequences in the printed verdict: at a fully handed-off size (vs the compiled bar) there is a `vs_compiled: "handed off"` and **no** `wins_vs_compiled` key, and the candidate's reported median equals the compiled median by construction ([check_candidate.py:386-394](../../../bench/grader/check_candidate.py)). The unpaired `reference` median is still timed at every size ([check_candidate.py:371](../../../bench/grader/check_candidate.py)) — informational only, as in round 3. This removes round 3's defect exactly: identical code can no longer be judged `slower` on paired noise (routing attempt-1's 2,048-row verdict, re-graded `same` by attempt-6; round-4 README *Refuted claims*).
- **What is new — the `own` rule and the baseline exception.** `own[name]` records whether a function ran code of its own in **any** part at that size ([check_candidate.py:364,382](../../../bench/grader/check_candidate.py)). A size's verdict against a bar is `handed off` only when neither the candidate nor that bar ran its own kernels there: `if not (own["candidate"] or own[bar])` ([check_candidate.py:387-390](../../../bench/grader/check_candidate.py)). For the compiled bar `own["compiled"]` is never set, so the rule reduces to "candidate handed off in every part". Against a `--baseline` attempt that runs its own kernels at a size the candidate hands off, the size **is** timed as before — candidate repeats copied from compiled against the baseline's own repeats ([ADR 0015:22](../../../claude/adr/0015-sets-and-hand-off-below.md)). For `routing+combine` the summing is per part before wins are counted (round 3 §1 stands), so one part handing off while the other runs still times the size, on the summed repeats.
- **What is new — `judge()`.** It filters `handed off` verdicts out of each phase before judging ([check_candidate.py:262-269](../../../bench/grader/check_candidate.py)); the phase rule and `beats_compiled` are *The exact boundary* item 4. The five synthetic cases in `test_hand_off.py` pin them (piece 4). G2 is untouched: correctness still runs at all six sizes through the dispatch, and timing still runs only when G2 passes ([check_candidate.py:349-352](../../../bench/grader/check_candidate.py)).
- **Cost:** the timing still chains 20 layers × 30 paired repeats per timed size (round 3 §1); handed-off sizes now cost one compiled timing instead of two identical ones per part. The one real-attempt evidence that the new reporting works end to end is Claude's re-grade of round 3's routing attempt-6 (`max_rows: 32`) with this grader: G2 passes, decode `faster` at 1/8/32 on 29/26/27 wins of 30, the three prefill sizes `handed off`, `beats_compiled` true ([ADR 0015:28-32](../../../claude/adr/0015-sets-and-hand-off-below.md)).
- **Invariants:** `WINS_NEEDED` is still 22 of 30 (one-sided sign test, p < 0.01, [check_candidate.py:56-63](../../../bench/grader/check_candidate.py)); size labels still carry the phase prefix (`rows ` / `prefill rows `) that `judge()` splits on ([check_candidate.py:57,358](../../../bench/grader/check_candidate.py)). A phase with every size handed off can never supply the required `faster` phase: an attempt that hands off everything beats nothing (`judge` case "everything handed off", piece 4).

### 3. `check_ready.py` — the set rule (check_ready.py:98-100, 152-174; time_candidates.py:111-132, 168-201)

- **Callers:** the lead only, `.venv/bin/python bench/grader/check_ready.py <new out folder> SLOT=FOLDER...`, at most twice per round (round-3 entry §5 stands: pinned protocol, log audit, `--audit`, exit codes). What round 4 changes is only how its verdict is read.
- **Where `muse-all` comes from.** `expected_variants` requires `compiled-all`/`muse-all` exactly when more than one slot is submitted ([check_ready.py:98-100](../../../bench/grader/check_ready.py)); `time_candidates.Variants` builds them by installing every slot's attempts (resp. compiled references) into one `MoE.__call__` ([time_candidates.py:117-127](../../../bench/grader/time_candidates.py)). `g3()` judges `muse-all` against `base` and `compiled-all` with the same range rule as any variant ([time_candidates.py:177-200](../../../bench/grader/time_candidates.py)), and the audit recomputes that verdict from the log before trusting it ([check_ready.py:142-148](../../../bench/grader/check_ready.py)).
- **The set rule, precisely.** The audit fills `judged[v]` for **every** `muse-*` variant — each single slot and `muse-all` — with `pass = g3[v]["g3"] and same_tokens` ([check_ready.py:152-161](../../../bench/grader/check_ready.py)). The set rule is **not** in this file's aggregate: the file still computes `passed = all(j["pass"] for j in judged.values())` and exits 0 only then ([check_ready.py:173-174](../../../bench/grader/check_ready.py)). So a set that passes only together produces `ready-verdict.json` with `pass: false` and exit 1, alongside `variants."muse-all".pass: true`. Readiness as a set is the skill's reading of that per-variant field (skill step 4: "when `muse-all` passes, all of them are `ready` together as a set, even where one fails alone"; brief:206). Any checker, tracker or script that reads only the top-level `pass`/exit code will report a passing set as failed — the single most misreadable line in the round-4 grader. The parts are still timed alone in the same run (the variants are all required by the audit), so the set reading costs no extra GPU run; a set's parts are not required to pass alone, but `muse-all` must still pass both bars and keep the tokens (`same_tokens` for `muse-all` at 1 and 32 requests, [check_ready.py:131-140,154-157](../../../bench/grader/check_ready.py)).
- **Data:** `ready-verdict.json` gains nothing new in round 4; the set is read out of the existing per-variant `variants`, `vs` and `phases` fields (round-3 entry §5). G3 after the round judges the set as `muse-all` in the same way ([ADR 0015:11,42](../../../claude/adr/0015-sets-and-hand-off-below.md)).
- **Invariants:** G3 and the ready-check protocol are unchanged ([ADR 0015:37](../../../claude/adr/0015-sets-and-hand-off-below.md)): a slot's kernels count wherever they run in a whole request, so the hand-off that the piece timing forgives is fully visible here — in particular at 1×128, where a `min_rows: 2` slot contributes the compiled reference's code, not its kernels (boundary item 5). Claude's post-round G3 stays the authority (round-3 entry §5).

### 4. `test_hand_off.py` — the unit check for pieces 1–2 (whole file)

- **What it checks.** With a toy combine kernel that copies `shared` (`out[i] = shared[i]`), `runs()` classifies each probed row count as `"kernel"` or `"compiled"` by bit-comparing the output against the toy output and against `mx.compile(ref_combine)` ([test_hand_off.py:21-54](../../../bench/grader/test_hand_off.py)). Four bound sets pin the dispatch and `hands_off` together at rows on both sides of each edge — no bounds; `max_rows: 32` (32 kernel, 33 compiled); `min_rows: 2` (1 compiled, 2 kernel); `min_rows: 8, max_rows: 59` (7 compiled, 8/59 kernel, 60 compiled) ([test_hand_off.py:65-74](../../../bench/grader/test_hand_off.py)). Four bad bounds must raise `ValueError`: `min_rows: 0`, `True`, `2.0`, and `min_rows: 33, max_rows: 32` ([test_hand_off.py:76-82](../../../bench/grader/test_hand_off.py)). Five synthetic verdict dicts pin `judge()`: all-timed with a slower prefill size (beats false); prefill handed off (beats true); 1 row handed off with 8/32 faster (beats true); a timed `same` blocking `faster` (beats false); everything handed off (beats false) ([test_hand_off.py:84-97](../../../bench/grader/test_hand_off.py)).
- **Callers / cost:** a standalone script (`.venv/bin/python bench/grader/test_hand_off.py`) using the GPU for a few small kernels, not the model ([test_hand_off.py:1-10](../../../bench/grader/test_hand_off.py)). ADR 0015 records it passed on 2026-11-04 ([ADR 0015:24-27](../../../claude/adr/0015-sets-and-hand-off-below.md)); this entry did not re-run it.
- **What it does not check:** any real slot, kernel or rounding (the toy output is exact by construction); the timing loop's exclusion/substitution and the `--baseline` exception in piece 2 (only the pure `judge()` is imported); per-part hand-offs in a `routing+combine` grade; and the set rule in piece 3, which has no unit test here at all. See *can't see* item 5.

### 5. The brief's slot interface — what builders see (muse-agent-brief.md:173-176, 206, 211-218)

- The brief now documents `min_rows` beside `max_rows` in the launch spec: integer ≥1, at most `max_rows`, kernels run only from `min_rows` to `max_rows`, with the 1-request G3 consequence stated in the same bullet (brief:173-174). It states that a hand-off is still G2-checked bit-exact at every size and that the piece timing reports the size as `handed off` (brief:175), that `routing+combine` carries both bounds per part (brief:176), the per-size/per-phase/`beats_compiled` reading of `handed off` (brief:216-218), and the set rule for the ready check and G3 (brief:206). The grader's printed per-size verdict list gains `handed off` as a fourth value (brief:211).
- **Invariant for builders and the boundary agent:** the brief, ADR 0015 and the code agree on the window, the phase rule and the set reading; the one place the wording runs ahead of the code is the ready check's aggregate verdict (piece 3), where the brief's "when that passes, the candidates are ready together" refers to `muse-all`'s own pass, not to `ready-verdict.json`'s top-level `pass`.

## Worked example: an experts attempt with `min_rows: 2, max_rows: 59`

The round-4 README's ungraded direction (round-4 README *What is left* item 1): round 3's experts attempt-1 kernels plus this window. `hands_off(rows)` is true at 1 row (`1 < 2`) and at every row above 59 ([slots.py:338-339](../../../bench/grader/slots.py)). Graded with no `--baseline`, so the only bar is `compiled`:

| Size | Phase | Who runs | G2 | Piece verdict vs compiled |
|---|---|---|---|---|
| 1 row | decode | compiled reference | compiled vs plain reference, bit-exact required | `handed off` — not timed; no `wins_vs_compiled`; candidate median = compiled median |
| 8 rows | decode | attempt's kernels | kernels vs `gather_qvm` reference, unsorted pairs | timed: `faster` iff ≥22/30 wins, `slower` iff ≥22 losses, else `same` |
| 32 rows | decode | attempt's kernels | kernels vs `gather_qvm` reference, sorted pairs (from 16 rows) | timed, same rule |
| 127 rows | prefill | compiled reference | compiled vs plain reference (`gather_qmm_rhs` side) | `handed off` |
| 1,016 rows | prefill | compiled reference | same | `handed off` |
| 2,048 rows | prefill | compiled reference | same | `handed off` |

Phase arithmetic ([check_candidate.py:253-271](../../../bench/grader/check_candidate.py)): decode keeps only 8 and 32 rows, so decode is `faster` iff **both** are `faster`, `slower` iff either is `slower`, else `not slower`. Prefill has no timed size left, so it is `handed off`. `beats_compiled` is therefore true exactly when 8 and 32 rows are both `faster`; a `same` at either makes decode `not slower` and `beats_compiled` false, and a `slower` at either makes it false with decode `slower`. For scale only (prediction, not a grade): round 3's attempt-1 kernels timed 168.9 vs 238.2 µs per layer at 8 rows and 554.7 vs 883.4 at 32 in their own run, while losing 96.9 vs 86.6 at 1 row ([ADR 0015:12](../../../claude/adr/0015-sets-and-hand-off-below.md); round-4 README *Per slot: experts*) — under the old rule that single `slower` made `beats_compiled` false; under this window the 1-row size is removed from the phase instead of having to be won. The kernels never face `gather_qmm_rhs` rounding: every row they run at is below 60, and every prefill size is handed off. Two cautions the table cannot show: rows 2–7 and 33–59 run the kernels in real serving but are graded at no size (only 8 and 32 represent the whole window), and at 1 request this attempt contributes nothing in G3 — alone it cannot be faster than its compiled bar at 1×128, so it passes whole requests only in a set whose other kernels win there (boundary item 5).

## What each tool still cannot see

Round 3's list stands except where the hand-off change retires it (its items 3 and 5c were already retired in round 3; the duplicate-timing half of its item 5 is now removed by piece 2). What round 4 adds or leaves open, per tool:

1. **`slots.build` cannot see where the window sits.** Any `max_rows` in 32..126, and any `min_rows` in 2..8, produce identical dispatch at the six G2 sizes on the far side of the tested points (32 runs the kernels, 127 hands off; 1 hands off for both `min_rows` values) — the piece grader cannot tell `max_rows: 59` (right side of the 60-row switch) from 100 (wrong side), and cannot see kernel speed or exactness at rows 2–7, 9–31 or 33–126 at all. `check_sizes.py` at 59/60/61 (round-3 entry §3) is still the only tool that places the experts hand-off, and only where the boundary agent runs it; hypotheses with kernels running above 32 rows carry the 33–59 band as **Unverified**.
2. **The piece timing cannot see the hand-off's own cost.** At a handed-off size the candidate is not run, so its reported time is the compiled bar's repeats copied over ([check_candidate.py:383](../../../bench/grader/check_candidate.py)); the `build` wrapper's dispatch branch and its separately compiled `mx.compile(REFERENCE[slot])` instance ([slots.py:336](../../../bench/grader/slots.py)) are never compared with the bar's own `mx.compile(ref)` wrapper at that size. In whole-request serving the muse variant goes through `build`'s `run()` while the compiled variant does not, so only G3/the ready check can show a wrapper cost — aggregated into whole-request ranges, never attributed to the hand-off.
3. **`judge()`'s all-or-nothing phase.** A phase is `faster` only when every timed size is; the size of a win is invisible to the verdict (a 300 µs win and a 1 µs win at 22/30 count the same), and one noisy `same` blocks `beats_compiled` even with large wins elsewhere (pinned deliberately by `test_hand_off.py`'s "a timed size not faster" case). Builders must read `timing_us_per_layer` magnitudes, not verdicts alone.
4. **`check_ready.py` cannot say "set" in its own verdict.** Its top-level `pass` and exit code still require every `muse-*` variant, singles included, to pass ([check_ready.py:173-174](../../../bench/grader/check_ready.py)); the set exists only in `variants."muse-all".pass` plus the skill's reading (piece 3). It also cannot attribute a `muse-all` result to its parts beyond the separately timed singles, cannot see per-slot contributions inside the combined `MoE.__call__`, and inherits round 3's items 6–7: 1-request whole-request verdicts are mostly noise-`same`, and a wholly invented log still passes the audit — only Claude's independent G3 catches it.
5. **`test_hand_off.py` cannot see the grader it guards.** It proves dispatch edges, bound refusal and `judge()` on synthetic verdicts with an exact-by-construction toy, but never runs `check_candidate`'s timing loop, a `routing+combine` two-part grade, the `--baseline` exception, a real experts kernel across the 60-row switch, or any part of the set rule (piece 4). A regression in the timing substitution at [check_candidate.py:376-394](../../../bench/grader/check_candidate.py) would pass this test suite.
6. **Handed-off exactness between the six sizes** still rests on compiled==reference where `check_sizes.py` has not run the attempt: G2 shows it at 1/8/32/127/1,016/2,048, `check_sizes` extends the hand-off path to its 25 sizes where run, and no tool tests above 2,048 rows (round-3 items 3 and 5 stand). Threadgroup memory, the link-kernel caveats and host-clock limits (round-3 items 8–9) are unchanged.

## Inefficiencies

None posted from this territory, and that is deliberate. The grader and the ready check run no decode-step kernels, so nothing here loses decode-step time in the sense of an inefficiency entry (cost at 1/8/32 decode rows and 127/1,016/2,048 prefill rows); round 4's changes in fact remove grader-side waste (identical code is no longer timed twice) and a false blocker (the set rule). The blind spots in *What each tool still cannot see* are contract limits, delivered here and as notes below instead of `ineff-grader-N` entries, as in round 3.
