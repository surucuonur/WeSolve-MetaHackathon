**Inefficiency:** the routing+combine pair keeps only −0.36 of its −0.66 ms/step piece win vs the compiled reference at 32×1024 and the 0.9% median gap sits inside the repeat spread — ~0.17 ms/step more separation passes (`../exploration/ineff-g3-1.md`, confirmed). The priced pools inside this slot are the per-row `w_router` re-read (excess 0 / 6.5 / 28.6 µs per layer at 1 / 8 / 32 rows; `ineff-baseline-routing-1.md`) and the staged scalar path's shape cost (27 barriers, 23%-duty tail third; single-digit µs per layer; `ineff-baseline-routing-2.md`). The two overlap: do not add.

**Slot:** `routing`. **Baseline:** none. **Starting point:** `muse-spark/round-3/kernels/routing/attempt-6` (byte-identical round-2 attempt-4 staged scalar kernels, `max_rows: 32`; G2 exact, decode `faster` ×3, prefill handed off; Claude's re-grade margins 17.7 / 15.8 / 19.7 µs per layer over compiled).

**Directions:** (a) share each `w_router` byte across rows (attack the re-read) while keeping the scalar accumulation order bit-exact; (b) trim the staged path's shape cost (barriers, tail duty, dead zeroing at 1 row) without touching the re-read. Both keep `max_rows: 32` so prefill stays handed off, and both must stay bit-exact at all six sizes — round 1's tiled-sharing attempt was slower everywhere, so direction (a) banks only if it holds the chained rate.

### What must stay identical — the exactness gates are closed; the fix widens the decode margin inside them (changed)

- **The arithmetic contract is unchanged.** Ordered bitwise equality at all six sizes (`differ = (inds != ref_inds).any(axis=1) | (w != ref_w).any(axis=1)`, `rows_differ == 0` in all 20 layers, `bench/grader/check_candidate.py:133,339-351`; `max_rel_err` still diagnostic-only, :134-136); the three `rows`-branched accumulation regimes with their exact orders (round-3 table still binds — a candidate branches on `rows`, never on the six graded values); the verbatim `1/(1+precise::exp(abs(s)))` sigmoid with the `(s<0)?y:1-y` branch; bias-add selection with unbiased gather; the `(((s0+s1)+s2)+s3)+1e-20`, divide, `×2.5` fold in emitted order. `ref_routing` is byte-unchanged, so the required evaluation is identical to rounds 2–3.
- **The tie rule for the 4th/5th expert and the order of the 4 pairs are unchanged.** Selection compares biased scores (`scores + bias`) with a strictly-greater insertion scan in ascending expert order, so the earliest index wins every exact tie — including an unseen exact tie between the 4th and 5th biased scores, and ties inside the top 4 — and positions 0..3 are emitted in descending biased-score order with `weights[r,j]` belonging to `inds[r,j]` at the same position `j` (`claude/muse-agent-brief.md:192`; `bench/grader/check_candidate.py:132-133`; starting point `block-0.metal:142-159`). No reordering of the 4 pairs is allowed; combine sums them in emitted order. A parallel top-4 (direction (b)) is legal only with index-ordered tie-breaking that reproduces this scan bit for bit.
- **Starting point against this boundary (identity changed, decode behaviour to keep unchanged).** Round 3's starting point was round-2 attempt-4 without a hand-off. Round 4's starting point `muse-spark/round-3/kernels/routing/attempt-6` is those same kernels byte-identically (`diff` empty this round) plus `"max_rows": 32`: it passes G1+G2 with 0 rows differing at all six sizes (`muse-spark/round-3/kernels/routing/attempt-6/grade.json`), decode `faster` ×3 under both graders (round-3 grade 28/27/25 wins; round-4 re-grade 29/26/27 wins, margins 17.7/15.8/19.7 µs/layer, `claude/adr/0015-sets-and-hand-off-below.md:28-32`). Its regime branches (`rows == 1` GEMV shuffle tree, `rows ≤ 768` split-K partition formula, single accumulator above, `block-0.metal:35-74`), verbatim sigmoid (:134-135), strictly-greater top-4 (:142-159) and weights fold (:160-173) are therefore the decode behaviour to keep: decode rows stay on this staged scalar path, and every decode step up to 32 rows must stay at or below the hand-off (see below). At kernel-visible counts only the GEMV (`rows == 1`) and split-K (1 < rows ≤ 32, 32 partitions × `base_iters = 1`) roundings ever run.
- **Hand-off retained at `max_rows: 32`; its piece-timing verdict changed to `handed off`.** With `"max_rows": 32` in `spec.json` (int ≥ 1, bools rejected, `bench/grader/slots.py:330-333`; `hands_off(rows)` is `rows > max_rows`, :338-339; `claude/muse-agent-brief.md:173`), inputs with `rows > 32` run the slot's reference under `mx.compile` through the attempt's own dispatch (`bench/grader/slots.py:341-345`). Round 3 timed those sizes against the compiled reference, so identical code could be judged `same` or, on paired noise, `slower` (round-3 attempt-1 at 2,048 rows). From round 4 such a size is reported `handed off` instead of being timed: the handing-off function is dropped from the paired repeats, takes the compiled repeats as its own times, and prints no `wins_vs_compiled` at that size (`bench/grader/check_candidate.py:372-394`; `claude/muse-agent-brief.md:211,216`). `judge()` then drops `handed off` sizes from their phase (`bench/grader/check_candidate.py:262-269`; brief:217-218): with `max_rows: 32` prefill (127/1,016/2,048) is `handed off` as a phase, decode is judged on 1/8/32 alone (`faster` iff all three are `faster`), and `beats_compiled` is true iff one phase is `faster` and neither is `slower` — here, iff decode is `faster`. This replaces round 3's "above `max_rows` the attempt times `same`, never better" and its paired prefill-timing bar: prefill is no longer timed for this slot at all, and a kernel fix needs no `same`-or-better prefill timing provided the hand-off stays. G2 still checks every handed-off size bit-exactly through the dispatch (`claude/muse-agent-brief.md:175`; `bench/grader/check_candidate.py:320-351`); the compiled reference was bit-exact with the reference at all six sizes on 2026-11-04 (`claude/adr/0011-decode-and-prefill.md:34`), and Claude's re-grade of this starting point under the round-4 grader shows the new reporting end to end: decode `faster` at 1/8/32 on 29/26/27 wins, prefill `handed off` ×3, `beats_compiled` true (`claude/adr/0015-sets-and-hand-off-below.md:28-32`).
- **Decode stays on the candidate: `max_rows: 32` and no `min_rows`.** A decode step has 1–32 rows (`claude/muse-agent-brief.md:26`); every decode step stays at or below the hand-off, running the staged scalar path that already wins there. `slots.build` now also accepts `"min_rows"` (int ≥ 1, at most `max_rows`, `bench/grader/slots.py:330-335`; brief:174), but the starting point carries none and an attempt for this hypothesis must keep it absent (`min_rows: 1` is the equivalent spelling): `min_rows > 1` would hand the smallest decode sizes — including the 1-row size, where this path's relative win is strongest — to the compiled reference, and with 1 request (1 row per step) the slot would then run MLX's own code for the whole request (brief:174). The window is therefore exactly 1 ≤ rows ≤ 32 on the kernels, rows > 32 on the compiled reference.
- **No MLX switch at 60 rows for this slot — the window stays 32 ≤ `max_rows` ≤ 126, fixed at its bottom.** The 60-row kernel change (`gather_qmm_rhs` vs `gather_qvm`) is the *experts* slot's (`bench/grader/slots.py:219-220`; `claude/muse-agent-brief.md:189`); routing's reference regimes change at `rows = 1` and `rows = 768` only. `max_rows: 32` keeps every decode step on the kernels and hands every graded prefill size (127/1,016/2,048) to compiled; the 33–126 band in real serving (vLLM chunked prefills) is empty by construction, exactly as round 3's boundary check found for attempt-1/attempt-6. Above `max_rows` the attempt's claim is unchanged in substance — "faster decode, unchanged prefill" (`claude/adr/0011-decode-and-prefill.md:35,48`) — only its piece-timing label changed, from timed `same` to `handed off`. The split-K-for-33–768 and single-accumulator branches are dead code at every reachable kernel count; if retained, they stay verbatim.
- **Consequence for the two directions** (this entry, *Directions*): (a) sharing each `w_router` byte across rows must reproduce the *same per-row regime orders* while sharing bytes — sharing bytes is free, reordering any row's accumulation (changing partition boundaries, sharding one expert's K across threads, or any serial-chain reorder) is a G2 failure; (b) trimming the staged path's shape cost (barriers, tail duty, dead zeroing at 1 row) keeps the same orders, sigmoid, tie rule and fold, and may widen the top-4 only as in the tie bullet above. Both keep `max_rows: 32` (prefill stays handed off — letting the kernels run at prefill sizes re-opens round 3's confirmed prefill losses and is not a saving under ADR 0011) and add no fixed cost at decode sizes that flips a `faster` to `same` (round 3's attempt-3 lesson: a ~2–3 µs copy launch did exactly that).

### The GPU limits (unchanged)

At most 1,024 threads per threadgroup and 32 KB of threadgroup memory (`claude/muse-agent-brief.md:100`); `grid` counts threads (`claude/muse-agent-brief.md:180`); Apple M1 Pro, 16 cores, SIMD width 32, `bfloat` in Metal (brief:101). Starting point for scale: 256 threads/threadgroup, `(816 + 60 + 2,048 + 4,096) × 4 B = 28,080 B` — 85.7% of the limit, leaving 4,688 B (`block-0.metal:15,22-25`); flat chained timing from 8 to 32 rows confirms the footprint does not bind residency at decode sizes, but any fix that stages more (wider cross-row groups, larger tiles) must re-derive this sum before it can be trusted. Enforcement gap stands: `slots.build` checks only the 1,024-thread product (`bench/grader/slots.py:349-350`); Metal's per-pipeline cap can sit below the brief's 1,024 and moves with the kernel (round 3: 960 threads refused at a 640 cap, 600 at 576, 480 the proven-passing band), so a sharing design sized only against 1,024 can still fail G1 as an opaque exception — group sizes must be proven against the pipeline cap, not the brief cap.
