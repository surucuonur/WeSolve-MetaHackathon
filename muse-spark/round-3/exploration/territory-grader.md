## What it does

Rounds 1 and 2's entries ([`muse-spark/exploration/territory-grader.md`](../../exploration/territory-grader.md) and [`muse-spark/round-2/exploration/territory-grader.md`](../../round-2/exploration/territory-grader.md), frozen) mapped the grader through ADR 0010: bit-exact G2 at six sizes, chained piece timing at decode sizes only, median-vs-median `beats_compiled`, and the paired sign-test `--baseline` bar. Round 3 changes the judgment ([ADR 0011](../../../claude/adr/0011-decode-and-prefill.md)): the piece timing runs at all six sizes with paired per-size verdicts, `beats_compiled` needs one phase faster and neither slower, and a spec may hand prefill-sized inputs to the compiled reference via `max_rows`. G3 moves to vLLM-only two-phase judgment (decode step, prompt time, whole-request time), and the lead's ready check ([`bench/grader/check_ready.py`](../../../bench/grader/check_ready.py), [ADR 0013](../../../claude/adr/0013-measure-what-you-claim.md)) runs that same G3 inside the round. This entry writes only the delta. G1/G2 mechanics, the spec language, `capture`, and `gpu_lock` are cited to rounds 1–2, not re-described.

## Checklist

### 1. `check_candidate.py` — paired per-size verdicts and the two-phase judgment (check_candidate.py:51-58, 224-264, 345-378)

- **Callers:** builders: `.venv/bin/python bench/grader/check_candidate.py <attempt> <slot> [--out FILE]` ([check_candidate.py:15](../../../bench/grader/check_candidate.py)); no `--baseline` this round — no slot has one (round-3 README *Starting point*). Holds the GPU lock for the whole run ([check_candidate.py:294](../../../bench/grader/check_candidate.py)). One grader run is one attempt (ADR 0013); builders keep `grade.json` in the attempt folder.
- **Callees:** unchanged: `slots.build`/`load_inputs`/`capture_prefill`/`load_model`; `mx.eval` for correctness and timing; `mx.compile(ref)` for the compiled bar only.
- **Data:** `ROWS = (1, 8, 32)`, `PHASES = {"decode": "rows ", "prefill": "prefill rows "}` ([check_candidate.py:51-52](../../../bench/grader/check_candidate.py)); `REPEATS = 30`, `WINS_NEEDED = 22` computed by the same one-sided sign test at p < 0.01 as round 2 ([check_candidate.py:53-58](../../../bench/grader/check_candidate.py)).
- **What is new — paired timing at all six sizes:** timing runs only if G2 passes ([check_candidate.py:345](../../../bench/grader/check_candidate.py)), over the same six size inputs as correctness (decode `load_inputs` + prefill `capture_prefill`, [check_candidate.py:308-312,349](../../../bench/grader/check_candidate.py)). Per size and part, `paired_times` runs candidate and compiled (plus baseline when given) in rotating order within each of 30 repeats, each repeat a full chained 20-layer eval ([check_candidate.py:224-236](../../../bench/grader/check_candidate.py)). Per-part times are summed per repeat before wins are counted ([check_candidate.py:364-366](../../../bench/grader/check_candidate.py)), so for `routing+combine` the verdict is on summed time, as in round 2. The plain `reference` is still timed by unpaired median `timed()` ([check_candidate.py:360](../../../bench/grader/check_candidate.py)) — informational only, no verdict against it.
- **What is new — `compare`/`judge`:** per size, the candidate is `faster` with ≥22 wins, `slower` with ≥22 losses, else `same` ([check_candidate.py:239-245](../../../bench/grader/check_candidate.py)). Per phase: `faster` iff every size is, `slower` iff any size is, else `not slower`; `beats_compiled` (and `beats_baseline`, same rule) is true iff one phase is `faster` and neither is `slower` ([check_candidate.py:248-264,377-378](../../../bench/grader/check_candidate.py)). Consequences: two `faster` + one `same` in a phase is `not slower`, not `faster` — a single noisy size now blocks the bar instead of passing it (round 2's median-only rule passed on noise up to 5%, [ADR 0011:26](../../../claude/adr/0011-decode-and-prefill.md)); a `same` everywhere attempt never beats.
- **Invariants:** verdict JSON gains per-size `wins_vs_compiled`/`vs_compiled` (and baseline twins) plus `phases_vs_compiled`/`beats_compiled` ([check_candidate.py:368-378](../../../bench/grader/check_candidate.py); brief:207). On G2 failure there is still no timing at all.

### 2. `slots.py` `build` — the `max_rows` hand-off (slots.py:304-337)

- **Callers:** `check_candidate.load` and `time_candidates.Variants`/`implementations`, via `slots.build(spec, sources, slot)` — so the hand-off applies identically in the piece timing, G2, G3 and the ready check.
- **What it does:** with `"max_rows"` in the spec (per part for `routing+combine`, brief:174), `run()` sends inputs with `rows > max_rows` to the slot's reference under `mx.compile` instead of the kernels ([slots.py:333-337](../../../bench/grader/slots.py)). `rows` is read from the first slot input's `shape[0]` ([slots.py:334](../../../bench/grader/slots.py)). Validation: int ≥ 1, bools rejected ([slots.py:327-331](../../../bench/grader/slots.py)); `compiled = mx.compile(REFERENCE[slot])` is built once per `build` call.
- **Grading:** "bit-exact, and timed at the prefill sizes" (brief:173). G2 checks `run()`, so sizes above `max_rows` exercise the compiled reference through the attempt's own dispatch; the compiled reference of each slot was bit-exact with the reference at all six sizes on 2026-11-04 (`bench/micro/compiled_exact.py`, `results/runs/2026-11-04-handoff-check/`, [ADR 0011:34](../../../claude/adr/0011-decode-and-prefill.md)). Timing above `max_rows` runs the bar's own code, so it reads `same` by construction, never better ([ADR 0011:35](../../../claude/adr/0011-decode-and-prefill.md)) — the claim for such an attempt is "faster decode, unchanged prefill" ([ADR 0011:48](../../../claude/adr/0011-decode-and-prefill.md)).
- **The experts switch at 60 rows:** from 60 rows MLX's own experts kernel changes (`gather_qmm_rhs` instead of `gather_qvm`) with different rounding ([slots.py:219-220](../../../bench/grader/slots.py); brief:187). Kernels running at rows ≥ 60 must match the large kernel's rounding; `max_rows` ≤ 59 keeps decode-built kernels on the `gather_qvm` side only. The boundary agent checks the hand-off sits on the right side of 60 for experts ([ADR 0011:47](../../../claude/adr/0011-decode-and-prefill.md)). Round 2's checked hand-off copy used `max_rows` 59 (`results/runs/2026-11-04-handoff-check/`).
- **What the grader cannot see here:** any `max_rows` in 32..126 behaves identically at all six G2 sizes and all six timing sizes (tested sizes on each side are 32 and 127) — the grader cannot tell 59 (right side of 60) from 100 (wrong side). §4's `check_sizes.py` (59/60/61) is what distinguishes them; see *What the grader still cannot see* item 1.

### 3. `capture_prefill`'s `tokens` parameter and `check_sizes.py` — G2 between the six sizes (slots.py:214-255; check_sizes.py)

- **New to these entries** (`check_sizes.py` arrived with Claude's "Measure round 2" commit `f679d23`, after round-2 exploration; the `tokens` parameter serves it). `capture_prefill(model, requests, with_weights, tokens)` with `tokens=N` records the first N tokens of a one-request prefill — N rows per layer ([slots.py:214-255](../../../bench/grader/slots.py)).
- **What it does:** `check_sizes.py <out.json> SLOT=FOLDER...` applies `check_candidate`'s checks and pass rule to every layer's slot inputs at `SIZES = (2,3,5,15,16,17,31,33,40,59,60,61,64,65,100,128,129,200,256,257,500,768,769,1024,1500)` ([check_sizes.py:26-27](../../../bench/grader/check_sizes.py)) — either side of the 16-row sort switch and the 60-row MLX switch, and inside each row-count regime an attempt names ([check_sizes.py:1-13](../../../bench/grader/check_sizes.py)). It loads the attempt's `run()` functions, so `max_rows` dispatch is exercised: sizes above `max_rows` test the hand-off path. GPU job under the lock ([check_sizes.py:38](../../../bench/grader/check_sizes.py)); prints per-size pass/FAIL and writes the report JSON.
- **Status:** boundary tooling, not a gate — G1/G2 still test exactly the six sizes. It closes round 2's *can't see* item 1 (branch-on-rows kernels exact at six sizes, wrong between) where the boundary agent runs it, and it is the tool that verifies a hand-off's side of 60.

### 4. `time_candidates.py` — two-phase vLLM G3 (time_candidates.py:51-55, 163-201, 204-265)

- **Callers:** Claude after the round; inside the round, only `check_ready.py` calls it (in-process, pinned argv). Plain-MLX mode still runs token checks and timing for diagnosis, but the G3 verdict reads vLLM runs only ([time_candidates.py:170](../../../bench/grader/time_candidates.py)).
- **Protocol:** `G3_SETTINGS = "1x128,8x128,32x128,32x1024"`, `G3_REPEATS = 5`, 256 output tokens ([time_candidates.py:51-55,217](../../../bench/grader/time_candidates.py)); vLLM with 512 MiB KV cache, 1 GiB when a prompt length exceeds 128 ([time_candidates.py:247-257](../../../bench/grader/time_candidates.py)).
- **What it times** (`MEASURES`, [time_candidates.py:54](../../../bench/grader/time_candidates.py)): `decode` = `period_median_ms`, the steady decode-step period; `prompt` = `prompt_ms`, first forward pass to the first step with no prompt tokens left — "until every prompt was processed" ([repeat_fixes.py:277-282](../../../bench/micro/repeat_fixes.py)); `request` = `wall_ms`, the whole run's wall time. Variants: `base`, `compiled-<slot>`, `muse-<slot>`, plus `compiled-all`/`muse-all` with several slots ([time_candidates.py:111-132](../../../bench/grader/time_candidates.py)) — a combination is measured as one, never summed.
- **The pass rule** (`against`/`g3`, [time_candidates.py:163-201](../../../bench/grader/time_candidates.py)): per setting and measure, `faster`/`slower` mean the two 5-repeat ranges don't overlap, else `same`. Per measure: `faster` iff every setting is, `slower` iff any is, else `not slower`. A `muse-*` variant passes against a bar iff decode or prompt is `faster` and none of the three is `slower`; `g3` needs that against both `base` and its `compiled-*` counterpart. A `muse-*` variant without its compiled counterpart is not judged ([time_candidates.py:179-181](../../../bench/grader/time_candidates.py)). Verdict to `g3-vllm.json`.
- **Why 5 repeats:** with 3, two identical engines' ranges miss per direction with p = 1/20, and 8 "never slower" checks per phase fail an unchanged phase ~1/3 of the time; with 5 it is 1/252 per check, ~3% over 8 ([ADR 0011:40](../../../claude/adr/0011-decode-and-prefill.md)). The motivating case: a hand-off copy at `max_rows` 59 read `slower` on prompt time at 32×1,024 by 0.5% (ranges 16 ms apart) although above 59 rows it *is* the compiled reference. Residual ~3% false-`slower` risk per phase stands.
- **Token checks:** `rf.vllm_checks` — greedy tokens (24, temperature 0) at 1 and 32 requests of 128-token prompts, plus one steady decode step's kernel count, per variant ([repeat_fixes.py:175-176](../../../bench/micro/repeat_fixes.py)).

### 5. `check_ready.py` — the in-round ready check (whole file)

- **Callers:** the lead only, at most twice per round (ADR 0013, skill v8). `.venv/bin/python bench/grader/check_ready.py <new out folder> SLOT=FOLDER...`, or `--audit <out folder>` ([check_ready.py:24-25](../../../bench/grader/check_ready.py)).
- **What it runs:** `time_candidates.py vllm` with the G3 protocol fixed in code — four workloads, 5 repeats, 256 tokens, every submitted slot in one call so the combination is measured as `muse-all` ([check_ready.py:48-56,81-86](../../../bench/grader/check_ready.py)). No flag changes the protocol; `check_protocol` stops before any GPU work if `time_candidates.py`'s G3 constants changed ([check_ready.py:63-70](../../../bench/grader/check_ready.py)). The out folder must be new ([check_ready.py:76-78](../../../bench/grader/check_ready.py)). Cost: ~10–15 min per slot, ~21 min for two, blocking builders' grader runs (ADR 0013).
- **What it audits** (the log, never the verdict file, [check_ready.py:103-150](../../../bench/grader/check_ready.py)): (1) exactly one `ready-check` marker with the protocol; (2) every timed run is vLLM at a G3 workload with 256 tokens and all three measurements present; (3) the variants are exactly `base`, `compiled-<slot>`/`muse-<slot>` per slot, plus `compiled-all`/`muse-all` with >1 slot, with repeats 0–4 at each workload; (4) every non-base variant keeps the unchanged model's greedy tokens at 1 and 32 requests — and a `compiled-*` variant that changes tokens is "no bar", invalidating the run ([check_ready.py:131-140](../../../bench/grader/check_ready.py)); (5) `g3-vllm.json` equals the G3 verdict recomputed from the log ([check_ready.py:142-148](../../../bench/grader/check_ready.py)).
- **What it writes:** `ready-verdict.json` — per `muse-*` variant its pass (G3 and same tokens), `vs` per bar, `phases` per bar, plus per-variant/workload/measurement median/min/max/n, `same_tokens`, `pass`, `judged`, `problems` ([check_ready.py:152-174](../../../bench/grader/check_ready.py)). Exit 0: every `muse-*` passes; 1: a variant fails — the verdict stands; 2: the run stopped or broke the protocol — no verdict, may rerun in a new folder ([check_ready.py:20-22,205-213](../../../bench/grader/check_ready.py)).
- **`--audit`:** re-checks a finished folder without the GPU; compares `pass`, `judged`, `variants`, `medians`, `same_tokens` against the saved `ready-verdict.json`, writes nothing, exits 2 on disagreement ([check_ready.py:195-203](../../../bench/grader/check_ready.py)). Used by the swarm's checker and by Claude after the round. Tested against 13 gaming tricks plus the control (`bench/grader/test_check_ready.py`, ADR 0013); verified live on round 2's submission (`results/runs/2026-11-04-ready-check/`, exit 1: routing fails on prompt time, combine on the decode step, the pair on all three).
- **Invariants:** only a passing verdict makes an attempt `ready`; Claude's post-round G3 stays the authority (ADR 0013).

## What the grader still cannot see

Round 2's list stands except item 3 (prefill speed — now timed) and item 5c (median-only `beats_compiled` — now a sign test at every size). What is new or still open:

1. **`max_rows` between the tested sizes.** Any value in 32..126 is identical at all six G2/timing sizes; the grader cannot see which side of 60 an experts hand-off sits on. `check_sizes.py` (59/60/61) closes it where the boundary agent runs it — the piece verdict never does.
2. **Kernel speed at 33–126 rows is unmeasured by the piece timing** (decode sizes stop at 32, prefill starts at 127). With `max_rows` > 32 the kernels run there in real serving (vLLM chunked prefills), and only G3's prompt time at its four workloads can show it — and only if a chunk lands there. Hypotheses with `max_rows` above 32 carry this as **Unverified**.
3. **Sizes above 2,048 rows** are tested nowhere (G2 stops at 2,048, `check_sizes` at 1,500); real prefill chunks reach 2,048 under `max_num_batched_tokens=2048`, so this is the top edge, not a gap in practice.
4. **Prefill beyond the first chunk** of 128-token seeded-random prompts, other prompt lengths, real-token distributions, mixed prefill+decode batches — unchanged from round 2. `check_sizes` varies the first chunk's length but nothing else.
5. **Hand-off exactness above `max_rows` at untested sizes** rests on compiled==reference there, shown at the six sizes (`results/runs/2026-11-04-handoff-check/`) plus the hand-off path at `SIZES` wherever `check_sizes` runs the attempt.
6. **Whole-request noise at 1 request:** repeats spread 6–41%, so G3/ready-check there mostly say `same` — which passes "never slower" without showing a gain ([ADR 0011:52](../../../claude/adr/0011-decode-and-prefill.md)). A real small gain hidden by noise is lost too, because a verdict stands (ADR 0013).
7. **A log invented whole** passes the audit; only Claude's independent G3 catches it ([ADR 0013:69-72](../../../claude/adr/0013-measure-what-you-claim.md)). Old logs without marker/token count are refused, not evidence.
8. **Threadgroup memory** still unchecked (only the ≤1024-thread product, [slots.py:341-342](../../../bench/grader/slots.py)); Metal rejects oversize kernels as opaque G1 exceptions.
9. **Link-kernel caveats carried over** (round-2 item 5a/b/d): 20 link kernels' additive cost in every timed eval; the 10% chain-fidelity figure unverified by the grader; host wall time with CPU dispatch inside; clocks unpinned.
10. **Plain-MLX behaviour is no longer gated** — G3 and the ready check judge vLLM runs only (`time_candidates plain` remains for diagnosis). Round 2's plain-vs-vLLM divergences (combine at 32, all-three at 8) are now visible in-round only through the ready check's vLLM lens.
