## What it does

Round 1's entry ([`muse-spark/exploration/territory-grader.md`](../../exploration/territory-grader.md), frozen) mapped the old grader: tolerance G2 (routing set-match + 1e-4 weights, combine/experts 2 ULP) at decode sizes 1/8/32 only, and independent (overlapped) piece timing. ADR 0010 ([`claude/adr/0010-exact-at-every-size.md`](../../../claude/adr/0010-exact-at-every-size.md)) changed three things, all in `bench/grader/check_candidate.py` and `bench/grader/slots.py`: **(1)** G2 is bit-exact and runs at six sizes — captured decode 1/8/32 rows plus live-captured prefill 127/1,016/2,048 rows ([ADR 0010:22-29](../../../claude/adr/0010-exact-at-every-size.md)); **(2)** the piece timing chains the 20 layers through a `link` kernel so calls cannot overlap ([ADR 0010:30-31](../../../claude/adr/0010-exact-at-every-size.md)); **(3)** `--baseline` (ADR 0009's bar) is timed in paired, rotating-order repeats and decided by a sign test ([`check_candidate.py:16-25`](../../../bench/grader/check_candidate.py)). This entry writes only the delta; unchanged machinery (spec build, `capture`, `gpu_lock`, `time_candidates`) is cited to round 1's entry, not re-described.

## Checklist

### 1. `slots.py` — slot table and references (slots.py:19-85)

- **Callers:** unchanged from round 1 — `check_candidate.py` (`SLOTS`, `REFERENCE`, `build`, `load_inputs`, model loaders) and `time_candidates.py` (round-1 entry items 1–3).
- **Callees:** `ref_routing` = sigmoid(`x` f32 @ `w_router.T`), `argpartition(-(scores+bias), kth=K-1)[:, :K]`, unbiased scores gathered, then `w / (w.sum + 1e-20) * 2.5` ([slots.py:44-48](../../../bench/grader/slots.py)); `ref_combine` = `(y * weights[..., None]).sum(-2)` → bf16 `+ shared` ([slots.py:51-52](../../../bench/grader/slots.py)); `ref_experts` = swiglu of two `gather_qmm` (affine int4, group 32) then a third, with `_gather_sort`/`_scatter_unsort` iff `do_sort = inds.size >= 64`, i.e. rows ≥ 16 ([slots.py:55-82](../../../bench/grader/slots.py)).
- **Data:** `D,E,K,H = 768,60,4,384`, `SCALE = 2.5` ([slots.py:19-20](../../../bench/grader/slots.py)); `SLOTS` input/output names per slot, `EXPERT_WEIGHTS` = `gate/up/down × w/scales/biases`, `routing+combine` = union of the two parts' inputs ([slots.py:29-40](../../../bench/grader/slots.py)).
- **What is new:** the references did not change, but what they *mean* did. At prefill sizes the same Python reference dispatches differently underneath: `ref_experts` is always on its sorted path (127+ rows ≫ 16), and inside `mx.gather_qmm` MLX switches from `gather_qvm` to `gather_qmm_rhs` at 60 rows, with different rounding ([ADR 0010:11](../../../claude/adr/0010-exact-at-every-size.md); [slots.py:219-220](../../../bench/grader/slots.py)). A candidate must therefore be bit-identical to *two* MLX kernels, or one design whose rounding matches both — the experts slot's central new constraint.
- **Invariants:** reference-vs-itself shows no difference at any size ([ADR 0010:29](../../../claude/adr/0010-exact-at-every-size.md)); `check_identity` still asserts the split MoE equals the port's at 1/8/32 rows ([slots.py:122-134](../../../bench/grader/slots.py)) — note it does *not* check identity at prefill sizes.

### 2. `slots.py` — `capture_prefill` and the input pipeline (slots.py:189-275)

- **Callers:** `check_candidate.main` builds the size list as decode `load_inputs(r, weights)` for `r in ROWS` plus prefill `capture_prefill(model, r, weights)` for `r in PROMPT_REQUESTS` ([check_candidate.py:269-276](../../../bench/grader/check_candidate.py)). The model is now loaded for *every* slot ([check_candidate.py:269](../../../bench/grader/check_candidate.py), `slots.load_model` [slots.py:189-199](../../../bench/grader/slots.py)); expert weights (`model_expert_weights`, [slots.py:202-203](../../../bench/grader/slots.py)) only when the slot is `experts`.
- **Callees:** `capture_prefill` swaps in a recording `make_moe_call(routing, combine)` (reference experts/shared run), seeds `mx.random.seed(requests)`, draws `(requests, 128)` random token ids, and runs one forward on the first chunk only: `model(ids[:, :chunk])` ([slots.py:229-248](../../../bench/grader/slots.py)). `chunk = min(bd.PREFILL_TOKENS // requests, 127)` with `PREFILL_TOKENS = 2048` ([slots.py:242](../../../bench/grader/slots.py); [breakdown.py:84](../../../bench/micro/breakdown.py)); each layer dict gains `inds` as u32 and, for experts, that layer's weights ([slots.py:249-254](../../../bench/grader/slots.py)), then `mx.eval(seen)`.
- **Data — the six G2 sizes:** requests 1/8/32 (`PROMPT_REQUESTS`, [slots.py:211](../../../bench/grader/slots.py)) × chunk 127/127/64 tokens, flattened by `MoE.__call__` to **127 / 1,016 / 2,048 rows** per layer ([slots.py:214-220](../../../bench/grader/slots.py) docstring). Together with the captured decode rows{1,8,32}.npz ([slots.py:257-275](../../../bench/grader/slots.py), round-1 entry item 2), every per-layer check below runs on 20 layers × 6 sizes × parts.
- **Neighbours:** the prompts are `time_candidates.py`'s (128-token random prompts, [slots.py:220](../../../bench/grader/slots.py)); prefill goes through the same `MoE.__call__` as decode ([slots.py:217-218](../../../bench/grader/slots.py)), which is the premise of testing it at all ([ADR 0010:16](../../../claude/adr/0010-exact-at-every-size.md)).
- **Cost:** grader runtime, not decode time: a 760 MB model load for every slot plus three live prefill chunks per run ([ADR 0010:40](../../../claude/adr/0010-exact-at-every-size.md)).

### 3. `slots.py` — launch-spec `build` (slots.py:303-345)

- **Delta:** none in the spec language, checks or chaining (round-1 entry item 3). One line matters for §7 below: the only GPU-limit check in code is the threadgroup *thread count*, `tg[0]*tg[1]*tg[2] > 1024` → ValueError ([slots.py:326-328](../../../bench/grader/slots.py)). There is no check of the brief's 32 KB threadgroup-memory limit, and no scan of the Metal source for threadgroup arrays; `atomic_outputs` is taken on trust ([slots.py:315](../../../bench/grader/slots.py)). An oversize kernel fails only if Metal compilation/execution rejects it, surfacing as a G1 exception (§4) with no grader-side attribution.
- **Invariants carried over:** `slot_outputs` must cover the slot's outputs ([slots.py:318-320](../../../bench/grader/slots.py)); sizes are ints or products of ints and `rows/D/E/K/H` only ([slots.py:282-292](../../../bench/grader/slots.py)); `rows` is read from the first slot input's `shape[0]` ([slots.py:323](../../../bench/grader/slots.py)), so one build serves all six sizes — a kernel cannot be specialised per size except by branching on shapes/strides inside Metal.

### 4. `check_candidate.py` — G1 and bit-exact G2 (check_candidate.py:90-175, 267-308)

- **Callers:** builders: `.venv/bin/python bench/grader/check_candidate.py <attempt> <slot> [--out FILE] [--baseline …]` ([check_candidate.py:13-14](../../../bench/grader/check_candidate.py)); holds the GPU lock for the whole run ([check_candidate.py:258](../../../bench/grader/check_candidate.py)).
- **Sizes loop:** for each of the six sizes, each part's check runs on all 20 layers ([check_candidate.py:277-304](../../../bench/grader/check_candidate.py)); the size label is `rows N` / `prefill rows N` from `layers[0]['x'].shape[0]`. Aggregation per part+size: `max` for `max_*` keys, `sum` otherwise, `pass` = every layer passes, first example kept as `worst_example` ([check_candidate.py:291-304](../../../bench/grader/check_candidate.py)).
- **G1:** `g1 = True` only after the whole correctness loop completes without exception ([check_candidate.py:306](../../../bench/grader/check_candidate.py)); any exception (spec load, Metal compile, model load, capture) is caught, trimmed by `short_error` ([check_candidate.py:231-241](../../../bench/grader/check_candidate.py)) and reported as `error` with `g1` false ([check_candidate.py:340-341](../../../bench/grader/check_candidate.py)). Per-layer shape/dtype faults are *not* exceptions — they become `{"error": …}` stats, so G1 stays true and G2 fails (unchanged mechanics, now over six sizes).
- **G2 routing** (`check_routing`, [check_candidate.py:102-136](../../../bench/grader/check_candidate.py)): exact shapes `(rows,4)`/`(rows,4)`, dtypes u32/f32, `inds < 60`; then **ordered bitwise equality**: a row differs iff `(inds != ref_inds).any(axis=1) | (w != ref_w).any(axis=1)` — float `!=`, no tolerance, order included "since combine sums the 4 pairs in this order" ([check_candidate.py:119-121](../../../bench/grader/check_candidate.py)). Diagnostics: `rows_other_experts` (rows whose expert *set* differs) and `max_rel_err`, the latter computed only over same-order rows ([check_candidate.py:122-128](../../../bench/grader/check_candidate.py)) — a permuted row's weight error is invisible in the diagnostic, though the row still fails the gate. `passes` requires `rows_differ == 0` ([check_candidate.py:172-175](../../../bench/grader/check_candidate.py)). **Gone vs round 1:** the set-match pass, the 1e-6 near-tie exemption that skipped the weight check, and the 1e-4 relative tolerance (round-1 entry item 4). The reference's own tie choice between the 4th and 5th expert, and its order, must now be reproduced exactly ([brief:187](../../../claude/muse-agent-brief.md)).
- **G2 combine/experts** (`differences`, [check_candidate.py:90-99](../../../bench/grader/check_candidate.py)): both sides cast bf16 → f32 and compared elementwise, `differ = (g != r) & ~(isnan(g) & isnan(r))` — NaN-vs-NaN counts as equal, everything else must be the same bits. `max_ulp` is **diagnostic only**: largest `|g−r| / ulp_bf16(r)` with the ULP floored at |r| = 0.001 ([check_candidate.py:84-99](../../../bench/grader/check_candidate.py)); overflow/NaN gaps clamp to 1e9. `check_combine` reports the first worst element as `row i column j` ([check_candidate.py:139-150](../../../bench/grader/check_candidate.py)); `check_experts` reshapes to `(rows, −1)` and decodes the flat index into row / expert slot / column ([check_candidate.py:153-169](../../../bench/grader/check_candidate.py)). `passes` requires `differ == 0`. **Gone vs round 1:** the 2-ULP pass ([brief:186-188](../../../claude/muse-agent-brief.md)); a single differing element in any layer at any of the six sizes fails G2, since global `g2 = all(s.get("pass"))` over every part+size ([check_candidate.py:308](../../../bench/grader/check_candidate.py)).
- **`routing+combine` independence (unchanged, still biting):** parts are loaded, checked and timed separately ([check_candidate.py:53-64](../../../bench/grader/check_candidate.py)); the combine part is fed the captured/candidate-independent `y/weights/shared` of each size, never the candidate routing part's output — so the piece G2 cannot see a routing+combine interaction, and passing both parts is sufficient only because each part is now bit-exact.

### 5. `check_candidate.py` — chained piece timing and the two bars (check_candidate.py:44-50, 178-228, 309-339)

- **Callers:** runs only if `g2` passes ([check_candidate.py:309](../../../bench/grader/check_candidate.py)), and only at the three *decode* sizes (`ROWS = (1, 8, 32)`, [check_candidate.py:44](../../../bench/grader/check_candidate.py)) on the captured decode inputs ([check_candidate.py:311-312](../../../bench/grader/check_candidate.py)) — prefill sizes are correctness-only.
- **The chain:** `link(a, prev) = a + (prev.reshape(-1)[:1] * 0)` as one `@mx.compile` fused kernel ([check_candidate.py:178-181](../../../bench/grader/check_candidate.py)). `chained` picks each part's smallest input (`min` by `size`: routing → `bias` [60], combine → `weights` [rows×4], experts → `inds` [rows×4]) and replaces it, from the second layer on, with `link(small, previous call's last output)`, so every call waits for the one before "as in a decode step" ([check_candidate.py:184-201](../../../bench/grader/check_candidate.py)). Every timed function — reference, compiled, candidate, baseline — gets the identical link; `mx.depends` was rejected because it orders only the graph ([ADR 0010:31](../../../claude/adr/0010-exact-at-every-size.md)). All 20 layers' outputs are kept alive until the single `mx.eval` (one GPU wait per repeat).
- **`timed`:** 3 warmup chained evals, then median of `REPEATS = 30` wall-clock (`perf_counter` around `mx.eval(chained(...))`) ÷ 20 → µs/layer ([check_candidate.py:204-213](../../../bench/grader/check_candidate.py)). This is the estimator for `reference` and `compiled` in all runs, and for `candidate` when no `--baseline` is given ([check_candidate.py:321-328](../../../bench/grader/check_candidate.py)); with several parts, per-part medians are summed into `row["candidate"]` etc.
- **`paired_times` (only with `--baseline`):** 3 warmups of each function, then per repeat the functions run in rotating order `[(i+k) % len]` so clock drift reaches both alike, each repeat a full chained 20-layer eval; per-repeat µs/layer per function ([check_candidate.py:216-228](../../../bench/grader/check_candidate.py)). Per row count, candidate and baseline times are accumulated *summed over parts per repeat* first ([check_candidate.py:323-326](../../../bench/grader/check_candidate.py)), so for `routing+combine` the wins are counted on the summed time, not per part. Verdict adds `baseline`, per-row `wins_vs_baseline`, and `wins_needed` ([check_candidate.py:261-266, 329-334](../../../bench/grader/check_candidate.py)).
- **What `beats_compiled` requires:** median `candidate < compiled` at **all three** row counts, strict, on the summed-over-parts medians ([check_candidate.py:334-335](../../../bench/grader/check_candidate.py)). No significance test — unlike the baseline rule, this compares medians alone, the practice ADR 0009 measured as noisy (same kernel vs itself: up to 5% between medians).
- **What `beats_baseline` requires:** candidate faster than baseline in at least `WINS_NEEDED` of the 30 paired repeats at **every** row count ([check_candidate.py:332-333](../../../bench/grader/check_candidate.py)). `WINS_NEEDED` is computed, not hardcoded: the smallest k with P(Bin(30, ½) ≥ k) < 0.01 → **22 of 30**, a one-sided sign test at p < 0.01 ([check_candidate.py:46-50](../../../bench/grader/check_candidate.py)). Both bars must hold for a slot to stop (brief's rule, [brief:201](../../../claude/muse-agent-brief.md)); the verdict reports them independently (`beats_compiled`, `beats_baseline`, [check_candidate.py:337-339](../../../bench/grader/check_candidate.py)).
- **Baseline loading:** `--baseline [SLOT=]FOLDER` (repeatable; for `routing+combine` one combined attempt or `routing=` + `combine=`) must cover exactly the slot's parts or the run exits ([check_candidate.py:67-81](../../../bench/grader/check_candidate.py)). **Round-2 state:** no slot has a baseline — no round-1 attempt passes the new G2 ([ADR 0010:38](../../../claude/adr/0010-exact-at-every-size.md); round-2 README *Starting point*) — so the operative bar this round is `beats_compiled` only; the paired machinery is the next rounds' bar.
- **Neighbours / what did not change:** end-to-end greedy-token equality (24 tokens, 1 and 32 requests, plain + vLLM) and G3 (median of 3 shuffled repeats, must beat base and compiled beyond spread) still live in `time_candidates.py` / the brief ([brief:191-192](../../../claude/muse-agent-brief.md); [ADR 0010:32-34](../../../claude/adr/0010-exact-at-every-size.md)); `check_candidate` is explicitly "a guide; G3 decides" ([brief:199](../../../claude/muse-agent-brief.md)).

### 6. Verdict shape (check_candidate.py:260, 336-345)

`{slot, g1, g2, beats_compiled, correctness: {"<part> <kind> <rows>": {…stats, pass, worst_example?}}, timing_us_per_layer: {"rows N": {reference, compiled, candidate[, baseline, wins_vs_baseline]}}, error?}` plus, with `--baseline`, `{baseline, beats_baseline, wins_needed: "22 of 30 paired repeats"}`; printed as JSON and written to `--out` when given ([check_candidate.py:260-266, 336-345](../../../bench/grader/check_candidate.py)). On G2 failure there is **no timing at all** — correctness stats are the whole verdict.

## What the grader still cannot see

1. **Row counts between the six tested ones.** Correctness sizes are exactly {1, 8, 32, 127, 1016, 2048} ([check_candidate.py:44, 272-276](../../../bench/grader/check_candidate.py); [slots.py:211](../../../bench/grader/slots.py)). Untested: 2–7, 9–31, 33–126, 128–1015, 1017–2047, >2048. Both internal thresholds are only *bracketed*, never pinpointed: the reference's sort at 16 rows sits between tested 8 and 32; MLX's `gather_qvm`→`gather_qmm_rhs` switch at 60 rows ([ADR 0010:11](../../../claude/adr/0010-exact-at-every-size.md)) sits between tested 32 and 127. A kernel that branches on `rows` (readable via `*_shape` in Metal) can be exact at all six sizes and wrong in between; the correct branch threshold must come from MLX's dispatch source (quantized-kernels territory), not from the grader.
2. **Prefill beyond the first chunk of 128-token random prompts.** `capture_prefill` records only `ids[:, :chunk]` of seeded random ids ([slots.py:240-246](../../../bench/grader/slots.py)). Later chunks (KV cache already filled), other prompt lengths, real-token distributions, and mixed prefill+decode batches are never presented to a candidate. Expert-popularity and tie distributions at the tested sizes are those of random tokens, not of real prompts.
3. **Prefill speed.** Timing loops over decode `ROWS` only ([check_candidate.py:311](../../../bench/grader/check_candidate.py)); a kernel slower at 127–2048 rows passes `beats_compiled` unnoticed apart from time-to-first-token ([ADR 0010:42](../../../claude/adr/0010-exact-at-every-size.md)). The 2048-row correctness run does exercise large grids, so gross grid/threadgroup breakage at scale is caught — slowness is not.
4. **Threadgroup memory.** Only the ≤1024-thread product is validated ([slots.py:327](../../../bench/grader/slots.py)); the 32 KB limit ([brief:98](../../../claude/muse-agent-brief.md)) is enforced, if at all, by Metal itself and reported only as an opaque G1 exception. Declared threadgroup arrays in the source are never measured by the grader.
5. **Timing dependence.** (a) Every timed eval includes 20 `link` kernels (one per layer) for every function alike — a fixed additive cost that "brings the reference and the candidate closer in relative terms, but not in µs" ([ADR 0010:41](../../../claude/adr/0010-exact-at-every-size.md)); percentage gaps in the piece timing understate the kernel-only gap. (b) The link hangs the chain on a single scalar of the previous call's *last* output through the *smallest* input; ADR 0010 reports this matches a real data chain within 10%, but the grader itself never verifies that figure. (c) `beats_compiled` is a median-only strict `<` ([check_candidate.py:335](../../../bench/grader/check_candidate.py)) while the same kernel timed twice differs by up to 5% between medians and the compiled reference varied up to 2× at 1 row between runs (ADR 0009) — a marginal `beats_compiled` can be noise in a way `beats_baseline` (sign test) cannot. (d) The measurement is host wall time around `mx.eval`, so CPU dispatch is inside the number; the GPU lock serialises runs but does not pin clocks. (e) Piece timing ≠ G3: round 1's experts starting point won overlapped, lost chained at 1 row, and the three slots together lost time each saved alone (round-2 README *Starting point*) — the chained timing fixes the overlap blindness, not the composition question (territory `g3`).
6. **Input diversity within a size.** Decode inputs are one captured step (step 8 of seeded 128-token random prompts, [slots.py:158-168](../../../bench/grader/slots.py) via round-1 item 2) and prefill inputs one seeded draw per request count. All 20 layers are covered at every size, but value-dependent behaviour (tie frequency, NaN/Inf paths, denormals) is sampled once; `differences` treats NaN-vs-NaN as equal ([check_candidate.py:93](../../../bench/grader/check_candidate.py)), so a kernel producing NaN exactly where the reference does passes — correctly, since the reference is the contract.

## Inefficiencies

None posted from this territory: the grader runs no decode-step kernels, and its blind spots (§ above) are contract limits, not lost decode time — per tracking.md (*Adapting to the others' work*) they are delivered as grader-side notes on the entries that own the cost instead of duplicate `ineff-grader-N` entries:

- `territory-baseline-experts` — prefill exactness (two MLX kernels' rounding; 60-row threshold bracketed, not pinpointed), chained 1-row timing as the operative bar, prefill slowness invisible.
- `territory-baseline-routing` — ordered bitwise equality incl. the reference's tie choice; `max_rel_err` diagnostic understates permuted rows; every currently-differing row fails.
- `territory-baseline-combine` — `differ == 0` gate with `max_ulp` demoted to diagnostic; a fix must hold at 2048 rows, not only at decode sizes; parts graded independently.
